## DOMの調査根拠

外部ページの文言・記事本文は保存せず、処理対象を判断するための構造とURLだけを記録する。

| 画面・URL | 確認できた構造・形式 |
|---|---|
| ホーム `https://note.com/` | 相対 `/tag/…` と絶対 `https://note.com/tag/…`。`/contest/…` は除外対象として区別 |
| 通常検索 `https://note.com/search?q=ComfyUI&context=note&mode=search` | `header[data-header-state="navbar"]` 内の `form[role="search"][action="/search"]` と `input[type="search"][name="q"]`。別の狭幅向け `form[role="search"]` はactionなし、`input[type="text"][aria-label="キーワードやクリエイターで検索"]` |
| 記事 `https://note.com/tender_yak5221/n/nbb5a8f31dfe3` | `https://note.com/hashtag/youtube`、URLエンコード済み日本語の `/hashtag/…`、関連枠の `/tag/K-POP` |

`tests/fixtures/note.html` は上記の構造から作った最小のDOM試料であり、note全画面のコピーではない。未確認の検索フォームへ汎用的にボタンを挿入しない。

ユーザーから、アンテナボタンの表示は問題なく、タグリンクの「通常クリックはタグページ、新規タブ表示は検索」という実画面結果を受領した（ブラウザ版・画面URLは未特定）。この結果に対応して、ON中の書き換え済みタグリンクの通常クリックだけをキャプチャ段階で補助する処理を追加した。サイトの旧URLへの遷移を再現した自動テストで検索URLへの遷移、修飾キー・別target・非対象リンクの除外、OFF時の解除を確認する。修正後のnote実画面での再確認は未実施として残す。

その後、ユーザーから画面上の動作成功と「設定を読み込めませんでした」の警告を受領した。警告だけでは元の例外を特定できない。旧コードが設定読込とDOM反映の例外を同じ警告にまとめ、追い越された読込失敗でも警告していたことを確認した。API失効時の終了・購読解除、古い失敗の無視、実際の読込失敗とDOM反映失敗の区別を追加し、自動テストで確認した。今回の警告修正後の実画面での再確認は未実施。

## 同一の受け入れ手順

各環境で対象ビルド・ブラウザ版・OS / 端末・読み込み方法を記録してから、次の手順を実施する。各手順の結果は「合格／不合格／未実施」とし、不合格にはURLと再現手順を添える。

| ID | 操作 | 期待する結果 |
|---|---|---|
| 01 | 初回読み込み後にnoteを再読込し、ホーム・記事・検索・タグ一覧・関連枠を確認 | 既定ON、確認済みのタグリンクだけが `q=#タグ名&context=note&mode=search&sort=new` の検索URLになる。記事・プロフィール・企画・外部リンクは変わらない |
| 02 | タグを通常クリック、戻る、修飾キー・ミドルクリックを実行 | 新着検索を表示。修飾キーやブラウザ標準の開き方を維持。サイトのSPAが旧URLへ誘導しない |
| 03 | リンクを右クリック（Androidは長押し）して新規タブで開く・リンクをコピー | どちらも変換後のURLを使用。独自メニューは出さない |
| 04 | note内をSPA遷移し、追加読み込み・タグ一覧・検索欄を再描画 | 新規リンクも変換、追加ボタンが重複しない。同じ要素のhref変更を古いURLで復元しない |
| 05 | 公式検索のEnter・虫眼鏡・サジェスト・日本語IME確定を使う | 公式の通常検索・入力操作を維持 |
| 06 | 「タグを新着検索」に `AI`、`#AI`、`＃AI`、空白、`#`だけを入力して実行 | 前3つは `#AI` の新着記事検索。空欄・記号だけでは遷移しない。日本語・C++も二重エンコードしない |
| 07 | ツールバー表示有無／Firefoxパネルからアクションを1回実行。Androidは通常ページの拡張メニューから項目をタップ | 1回だけOFFに反転。既存hrefが復元され、ボタンが消える。タイトル・バッジを確認。Androidはメニューを開き直して状態を読める |
| 08 | OFFのまま手順03・04を行い、別のnoteタブからON、通常のnote以外のページからOFF | OFFでは元のリンク。全ての開いたnoteタブへ再読込なしに反映。別ブラウザ・別プロファイルとは同期しない |
| 09 | アクションを素早く連続操作し、backgroundを自然休止させてから再操作 | クリック回数どおりに反転。保存値と画面・タイトルが一致。常駐DevToolsによる休止抑制を避ける |
| 10 | ON・OFFそれぞれでブラウザ再起動、Androidはアプリ休止・タブ破棄と復帰も実施 | 同一プロファイルの状態を維持。復帰タブは最新の保存値を再確認。Firefoxの一時拡張が外れた状態は試験不成立として区別 |
| 11 | noteへのサイトアクセスを許可／拒否した状態で確認 | 許可時だけページ変更。トグルがサイト権限を勝手に解除しない。ホームや内部ページに導線がない場合は通常Webページから操作可能 |
| 12 | 狭幅・タッチ・キーボードで追加ボタンを確認し、記事閲覧・購入導線等を確認 | ボタンが検索欄の近くで操作可能、フォーカス表示とラベルあり。公式フォーム・他の操作を壊さない |

## 再試験方法と公開前の残条件

- 自動テスト：`npm ci --ignore-scripts` → `npm test`。
- 配布物：`npm run package` → `npm run lint:firefox`。生成を繰り返しても同一ソースのZIPハッシュが一致することを確認する。
- Firefox Desktop：`npx --no-install web-ext run --source-dir dist/firefox --no-config-discovery`。専用の一時プロファイルを使用する。
- Android：ADB接続後、READMEの `web-ext run --target firefox-android` 手順で読み込み、Desktopの `about:debugging` からログとDOMを調査する。
- Firefoxの一時読み込みは再起動で解除される。開発用の永続読み込みが可能な専用環境での結果は条件を記録し、通常の署名済み配布での再起動試験は将来の署名後に行う。
- Firefox IDのAMO一意性確認・署名・申請は未実施。最低版・現行版の実画面検証が残っているため、全ブラウザの受け入れ完了とはしない。
- ストア申請、AMOへの署名要求、GitHub Release、Gitタグ作成は実行しない。
